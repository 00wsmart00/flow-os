# FlowOS 路线图概览

本文件用于跨会话快速定位当前阶段；完整范围、退出门槛和长期阶段见 [development-plan.md](development-plan.md)。状态以代码、迁移和测试为准。

| 阶段 | 当前状态 | 已有结果 | 主要剩余项 |
|---|---|---|---|
| 0. 基线与决策 | 部分完成 | Git 基线、远程仓库、架构/产品/合规文档、统一错误契约 | CI、一次性 PostgreSQL、领域相关方确认 |
| 1. 订单与物料需求 | 已实现，待提交与评审 | 订单列表/详情、游标分页、订单行、产品、物料、版本化 BOM、需求展开 | 更多异常契约、正式业务规则确认 |
| 2. 库存与缺口 | 已实现窄范围，待提交与评审 | 最终库存快照、供应位置、缺口纯计算、来源和警告 | 新鲜度、批次/颜色、供应资格、单位换算策略 |
| 3. 采购建议草稿 | 下一阶段 | 仅有产品与业务规则边界 | 草稿/明细、幂等键、任务状态、审计事件、并发控制 |
| 4. 结构化 Web 工作流 | 未开始 | `frontend/` 占位 | React/TypeScript/Vite、API 客户端和端到端流程 |
| 5. 生产就绪 | 未开始 | 健康检查和本地容器基础 | 身份、授权、租户、可观测性、备份恢复和安全审查 |
| 6+. Agent、报价、APS | 延后 | 长期方向文档 | 以前序确定性流程和治理证据为前置条件 |

## 当前推荐顺序

1. 评审并提交当前阶段 1–2 的未提交代码和文档。
2. 补 CI、迁移验证和一次性 PostgreSQL 集成环境。
3. 确认阶段 3 所需采购舍入、幂等、任务状态与审计规则。
4. 实现无约束力的采购建议草稿；不得创建采购订单或联系供应商。
5. API 稳定后再初始化完整前端工作流。

若用户给出新的明确优先级，以最新需求为准，并同步更新本文件和 `.codex-context`。
