# 业务规则基线

## 状态

以下内容是 V0.1 的产品级规则占位，不是从任何现有企业复制的业务规则。实现前，必须使用合成示例并由获得授权的业务相关方确认每一项规则。

## 订单查询

- 查询必须限定在已记录的字段范围内，并限制最大返回数量。
- 订单标识在未来的租户边界内唯一。
- 只有明确允许的订单状态才能进入缺口分析；具体状态集合仍需产品决策。
- API 契约必须明确表达日期、数量、单位和币种。

## 库存缺口

未来的计算应放在纯 `domain` 层中，不得依赖 ORM：

```text
总需求量 = 订单需求量 × 单耗 + 明确的附加用量
可用供应量 = 合格现存量 − 保护库存 − 已有占用 + 合格在途量
缺口 = max(0, 总需求量 − 可用供应量)
```

该公式只是中立的初始假设。单位换算、损耗、批次与颜色约束、在途量资格、分配优先级、舍入和保护库存策略，都必须分别建模并经过确认。

每个计算结果都必须保留足以解释结果的输入快照和规则版本。

## 采购建议草稿

- 采购建议是无约束力的草稿，不是采购订单。
- 建议数量必须来自可解释的缺口，以及明确的舍入和最小订购规则。
- 供应商、价格、交期、税费和商务条款必须由人工确认。
- 向供应商或下游采购系统提交数据不属于 V0.1 范围。

## 仅使用合成示例

示例必须使用容易识别的合成标识，例如 `SYN-SO-0001`，并使用虚构的组织名称。不得使用真实企业的规则、编码、数量、价格或命名约定。
