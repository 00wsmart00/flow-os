# 业务规则基线

## 状态

以下内容是 V0.1 的产品级规则基线，不是从任何现有企业复制的业务规则。当前实现使用合成示例验证；进入真实业务试点前，必须由获得授权的业务相关方确认。

## 订单查询

- 查询必须限定在已记录的字段范围内，并限制最大返回数量。
- 订单标识在未来的租户边界内唯一。
- V0.1 只有 `confirmed` 订单可以展开物料需求；其他状态返回可操作的冲突错误。
- API 契约必须明确表达日期、数量、单位和币种。

## 订单行与 BOM 版本

- 每张订单至少包含一条显式的订单行，记录产品、数量、单位，并可记录颜色和尺码。
- 每条参与计算的订单行必须显式绑定一个 BOM 版本，计算时不得隐式选择“最新版本”。
- BOM 必须属于订单行产品，状态为 `active`，且在订单日期生效。
- BOM 以 `base_quantity` 表达基准产品数量，每项物料记录基准用量、单位、损耗率和向上舍入增量。
- 当前增量不执行单位换算；订单行单位必须等于产品基础单位，BOM 明细单位必须等于物料单位，否则拒绝计算。
- 损耗率允许范围为 0–100，所有数量和舍入增量必须大于零。
- 当前规则版本为 `material-requirement-v1`。

物料需求按以下纯领域规则计算：

```text
原始需求量 = 订单数量 ÷ BOM 基准数量 × BOM 单耗 × (1 + 损耗率 ÷ 100)
最终需求量 = 原始需求量按 BOM 明细的舍入增量向上取整
```

## 库存缺口

计算放在纯 `domain` 层中，不依赖 ORM，并且必须显式引用一个状态为 `final` 的库存快照：

```text
总需求量 = 已展开的最终物料需求量 + 明确的附加用量
可用供应量 = 合格现存量 − 保护库存 − 已有占用 + 合格在途量
缺口 = max(0, 总需求量 − 可用供应量)
```

- 快照包含采集时间、来源，以及按物料和库位拆分的供应位置。
- 当前规则只接受非负的现存量、保护库存、占用、合格在途量和被排除在途量。
- 当前增量不执行供应单位换算；供应位置单位必须与物料需求单位一致。
- 被排除在途量只用于解释，不进入可用供应量。
- 没有供应位置时按零供应计算，并返回 `no_supply_position` 警告。
- 当保护库存和占用超过供应时保留负可用量，并返回 `negative_available_supply` 警告，使结果可解释。
- 当前缺口规则版本为 `shortage-v1`。

该公式仍是需要业务确认的初始假设。单位换算、批次与颜色约束、在途量资格、分配优先级和保护库存策略，都必须分别建模并经过确认。

每个计算结果都必须保留足以解释结果的输入快照和规则版本。

## 采购建议草稿

- 采购建议是无约束力的草稿，不是采购订单。
- 建议数量必须来自可解释的缺口，以及明确的舍入和最小订购规则。
- 供应商、价格、交期、税费和商务条款必须由人工确认。
- 向供应商或下游采购系统提交数据不属于 V0.1 范围。

## 仅使用合成示例

示例必须使用容易识别的合成标识，例如 `SYN-SO-0001`，并使用虚构的组织名称。不得使用真实企业的规则、编码、数量、价格或命名约定。
